# 시간과 밀도

## 왜 멈춤 구간인가

전체를 같은 비율로 느리게 하면 짧은 장은 여전히 못 읽고 긴 장(배치 전환)은 늘어진다. 그래서
**사건은 제 속도로 일어나고, 각 단계가 다 나온 뒤에 읽을 시간만큼 이야기를 멈춘다.** 멈춤 동안 패킷은
계속 흐르고 자막·말풍선은 그대로 있다. 기본 재생 배율 `M.base = 0.5` 는 사건 자체도 천천히 보이게 한다
(실제 피드백: 30초 → "빠르다", 멈춤 추가 후 2분 → "여전히 빠르다", 지금의 0.5배를 1배로 → 만족).

## 장 길이 정하기

실제 재생 초 기준:

```
장 길이 ≈ 자막(제목+본문) 글자 수 ÷ 9  +  그 장 말풍선 글자 수 ÷ 27  +  1.5
```

- 글자 수는 공백 제외. 자막은 꼼꼼히 읽고(초당 9자), 말풍선은 자막과 겹치는 내용이 많아 훑는다(초당 27자)
- 경과 기록처럼 한 줄씩 늘어나는 핵심 목록은 줄마다 2.5~3초(이야기 시각 기준 멈춤)
- 이야기 시각의 멈춤 합 = (장 길이 × base) − 그 장의 이야기 길이

예: 자막 120자, 말풍선 150자 → 13.3 + 5.6 + 1.5 ≈ 20초(실제). 이야기 4초짜리 장이면 멈춤 합 = 20×0.5 − 4 = 6초.

측정은 브라우저에서 바로 할 수 있다:

```js
M.caps.map(c => (c.title + c.body).replace(/\s/g, '').length)
```

## 멈춤을 어디에 둘까

- 말풍선이 나타나는 장면: `t0 + fade(0.35) + 0.05` 이후에 멈춘다. 말풍선이 여러 개면 0.3~0.4초 간격으로 띄우고 각각 뒤에 멈춤
- 장 끝: 말풍선이 사라지기 시작하는 `t1 − fade` **전에** 멈춘다
- 배치 전환(morph): 전환 전(새 역할 띠만 보이는 상태)과 전환이 끝난 뒤에 둔다. `B.morph` 의 반환값이 끝나는 시각
- 카운터: 숫자가 다 오른 뒤. 오르는 시간은 0.5~2초(이야기 시각)로 짧게
- 장애 시계: 시계도 이야기 시각을 따르므로 멈춤 동안 함께 멈춘다 — 자연스럽다

## 밀도 기본값

| 요소 | 기본 | 이유 |
|---|---|---|
| 요청 패킷 | 대상 3개 중 1개에만, 흐름당 1개 | 선은 전부 그려 배치를 보이고, 움직임은 "흐른다"는 느낌만 |
| 흐름선 투명도 | 0.32 | 칩·글자를 가리지 않게 |
| 보조 흐름(DB·캡처·스냅샷) | 대표 1줄 | 주제가 아닌 흐름은 존재만 알린다 |
| 수집(로그·메트릭) | 구역당 1줄, 수집기는 1개만 패킷 | 구역 수만큼 늘어나 금방 붐빈다 |
| 동시에 도는 흐름 | 그 장의 주제 흐름만 | 평상시 흐름을 장애 장면까지 끌고 가지 않는다 |
