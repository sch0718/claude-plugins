# 아키텍처 모션 그래픽

명령 안의 `<스킬 폴더>`는 이 스킬을 불러올 때 알려 주는 기본 폴더(Base directory)다.

시스템이 **어떻게 바뀌었고, 그 안에서 요청이 어떻게 흐르며, 장애가 나면 무엇이 달라지는지**를
재생 막대가 있는 웹 애니메이션으로 만든다. 결과물은 폐쇄망에서도 열리는 정적 HTML 묶음이다.
**MP4·GIF 변환은 하지 않는다**(사용자 결정 — HTML 만으로 충분). 영상 파일을 요청받으면 HTML 로 만들고,
영상이 꼭 필요하면 사용자가 브라우저 화면 녹화로 만들 수 있다고만 안내한다.

엔진(`assets/motion.js`)이 타임라인·패킷 흐름·말풍선·자막·재생 UI·관점 전환을 이미 갖고 있어서,
작업자는 **사실 정리 → 배치(diagram.js) → 장면(scenes.js) → 점검**에만 집중하면 된다.
완성 예시는 `examples/sample-cluster/`(가상 웹 서비스의 노드 재배치, 관점 2개, 약 1분)다.
처음이면 이 예시의 `scenes.js`를 먼저 훑어보면 API가 어떻게 쓰이는지 가장 빨리 보인다.

## 결과물 구조

```
<프로젝트 폴더>/            # git 에 넣지 않을 곳(예: dist/) — 먼저 git check-ignore 로 확인
├── index.html   뷰어 (고치지 않는다: 관점 토글·재생 막대·속도·점검용 캡처 모드)
├── motion.js    엔진 (고치지 않는다)
├── motion.css   스타일 (고치지 않는다 — 색은 WCAG AA 대비·색+아이콘 병행으로 맞춰 둠)
├── diagram.js   이 시스템의 배치: 구역·칩·레이아웃·바깥 상자·상태 패널·흐름 묶음
└── scenes.js    관점별 타임라인: 장·멈춤·흐름·말풍선·자막
```

시작은 템플릿 복사다. 템플릿은 그대로 돌아가는 작은 예제(서버 3대 재배치)라서 고쳐 나가면 된다.

```bash
cp <스킬 폴더>/assets/{index.html,motion.js,motion.css,diagram.js,scenes.js} <프로젝트 폴더>/
```

## 작업 순서

### 1. 사실부터 모은다

그래픽은 설명 자료라서, 틀린 숫자 하나가 전체 신뢰를 깎는다. 구성·수치·시각은 설계 문서·장애 보고서·
차트 값·로그에서 가져오고, 장면마다 출처를 메모해 둔다(사용자에게 마지막에 보고한다).

- 문서에 **추정**이라고 된 것은 그래픽에도 "(추정)"을 붙인다. 원인이 확정되지 않은 것을 단정하지 않는다.
- 문서에 없는 배치(어떤 Pod가 어느 노드에 있었는지 등)를 그려야 하면 "설명용 배치"라고 보고한다.
- 운영 IP·호스트명·계정·내부 티켓 번호는 넣지 않는다. 청중에게 의미 없는 내부 번호(PR 번호 등)도 뺀다.
- 이미 고쳐진 결함은 "있었으나 지금은 수정·반영됨"으로 쓴다. 바뀐 구성이 막지 못하는 것(외부 DB 장애 등)은
  **한계**로 따로 밝힌다 — 구성 변경이 모든 것을 해결한 것처럼 보이면 리뷰에서 바로 지적받는다.
- 모르는 것은 추측하지 말고 묻는다.

### 2. 보는 사람과 방향을 정한다

보는 사람(IT팀·아키텍처 리뷰 / 경영진·현업 / 감사·통제 담당)에 따라 용어와 세부가 달라지므로 먼저 한 번 묻는다.
IT팀이면 실제 구성요소 이름(node1~4, taint, ES 복제)을 쓰고, 경영진이면 "서버 4대", "감시 화면"처럼 바꾼다.

방향은 아래 두 가지가 실제로 좋은 반응을 얻었다. 둘 다 만들어 관점 토글로 묶는 것이 가장 좋았다.

| 관점 | 흐름 | 강점 |
|---|---|---|
| **구성 변화** | 이전 구성의 평상시 흐름(요청·배치·관측) → 실제 장애 재현 → 배치가 바뀌는 전환 장면 → 이후 구성에서 같은 종류의 장애 → 정리 표 | 왜 바꿨는지가 이야기로 이어진다 |
| **장애 시계** | 화면 위 시계 + 경과 기록이 한 줄씩 늘어남 → 되감기 → "바뀐 구성이었다면?"을 초 단위로 | 장애 대응 차이가 가장 강하게 전달된다 |

**화면을 위아래·좌우로 나눠 이전/이후를 동시에 재생하는 방식은 피한다.** 16:9 무대를 반으로 나누면
글자가 7~9px 수준으로 작아지고 시선이 갈라져, 실제로 "별로"라는 평가를 받았다.

시안을 여러 개 보여줄 때는 장면 구성을 채팅으로 먼저 설명하고 승인을 받은 뒤 만든다.

### 3. 배치를 그린다 — diagram.js

`M.board(G, { layout, chips, title })` 로 구역(서버·노드)과 칩(Pod·프로세스)을 만든다. 칩마다 레이아웃별
자리(`at: { before: [구역, 칸], after: [구역, 칸] }`)를 주면 `B.morph('before', 'after', ...)` 한 줄로
재배치 장면이 나온다. 바깥 시스템은 `B.addBox`, 대시보드·감시 화면은 `B.addPanel`.
자주 쓰는 흐름(요청 왕복, 로그 수집 등)은 `B.req` 같은 묶음 함수로 diagram.js 안에 만들어 둔다.
API 전체와 함정은 `references/engine-api.md`.

### 4. 장면을 쓴다 — scenes.js

장(chapter)마다 **흐름 → 말풍선(강조) → 자막(설명)** 순서로 놓는다. 자막은 장 전체에 걸쳐 하나,
말풍선은 그 장의 핵심 한두 개다. 장애 장면은 원인 → 증폭 → 확산 → 인지 순으로 사건을 하나씩 띄운다.

장애를 "가정"해서 보여줄 때(바뀐 구성에서 노드 1대가 죽는다면):
- **트래픽이 덜 지나가는 구역을 고른다.** 진입점 바로 옆 구역을 죽이면 장애 표시가 다른 구역으로 가는 선을 덮는다
  (실제로 node1→node3으로 바꿨다). 엔진은 장애 표시를 패킷 아래에 그려서 지나가는 패킷은 보이게 한다.
- **숫자는 그 구역의 실제 배치로 다시 센다.** 4/3/3 배치에서 3대짜리 구역이 죽으면 7/10이지 6/10이 아니다.
  설계 문서의 "약 60~64%" 같은 일반 수치와 다를 수 있으니 보고 때 함께 알린다.

### 5. 시간을 정한다 — 가장 자주 지적받는 부분

처음 만든 30초짜리는 "너무 빠르다"는 피드백을 두 번 받았다. 지금 엔진은 기본 재생 배율(`M.base = 0.5`)과
장면별 **멈춤 구간(holds)** 으로 읽을 시간을 준다. 멈춤 동안에도 패킷은 계속 움직여 화면이 죽지 않는다.

- 장 길이(실제 재생 초) ≈ 자막 글자 수 ÷ 9 + 말풍선 글자 수 ÷ 27 + 1.5
- 멈춤은 각 말풍선이 **다 나타난 뒤**(나타난 시각 + 0.4초 이후), **사라지기 시작하기 전**에 둔다
- 숫자가 올라가는 카운터는 멈춤 전에 다 오르게 한다(멈춤이 숫자를 중간값에 얼려 버린다)
- 배치 전환(morph) 도중에는 멈추지 않는다 — 칩이 공중에 뜬 채 멈춘다

계산 방법과 예시는 `references/timing.md`. 재생 막대의 속도(0.5×~2×)로 보는 사람이 조절할 수 있다.

### 6. 덜 붐비게 한다

패킷이 많으면 무엇이 중요한지 안 보인다("트래픽 요소가 너무 많다"는 피드백). 기본값으로:
- 요청 패킷은 대상 칩 3개 중 1개에만, 흐름당 패킷 1개, 선은 옅게(배치는 선으로 보이게 전부 그린다)
- 한 장면에서 동시에 도는 흐름은 그 장의 주제 흐름만. 평상시 흐름을 장애 장면까지 다 끌고 가지 않는다

### 7. 점검한다 — 사용자에게 보이기 전에

```bash
cd <스킬 폴더>/scripts && [ -d node_modules ] || npm i --no-audit --no-fund
node <스킬 폴더>/scripts/check.mjs <프로젝트 폴더> --out <캡처 폴더>
```

헤드리스 Chrome(이 PC의 Chrome 사용)으로 관점마다 전 구간을 그려 보고 다음을 알려 준다:
렌더 오류·브라우저 오류, 말풍선·칩·상자의 글자 넘침, 말풍선끼리 겹침·무대 밖·자막 가림, 자막 넘침,
**반투명한 채 멈춤**(멈춤 위치 잘못), 자막 없는 구간. 경고를 0으로 만든 뒤, 캡처를 몇 장(장애 장면,
전환 직후, 마지막) Read 로 직접 열어 눈으로도 본다 — 스크립트는 "어색함"까지는 못 잡는다.

사용자에게 보여줄 때는 `.claude/launch.json` 에 정적 서버(`python3 -m http.server <포트> --directory <폴더>`)를
추가해 브라우저 창으로 띄운다. 파일을 직접 여는 file:// 미리보기는 스크립트가 붙지 않는 경우가 있다.
브라우저 창이 가려져 있으면 requestAnimationFrame 이 멈춰 실시간 재생 확인이 안 되니, 그때는
`M.seekStory(초)` 로 장면을 옮겨 확인하고 "실시간 재생은 확인 못 함"이라고 보고한다.
