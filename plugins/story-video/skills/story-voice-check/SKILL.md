# 6. 낭독 검증

명령 안의 `<플러그인>`은 `${CLAUDE_PLUGIN_ROOT}`(비어 있으면 이 스킬 기본 폴더의 `../..`)다.

| | |
|---|---|
| 입력 | `story.json`, `out/timeline.json`(문장마다 음성 파일), `voice/`, `out/voices.json`(있으면) |
| 출력 | `out/voice-check.json`, `out/voice-check.md`. 고친 문장이 있으면 `story.json`의 그 줄에 `take`(와 `say`)가 들어가고 `out/timeline.json`·`subtitles.srt`·`audio.wav`가 다시 만들어진다 |
| 다음 | `story-visual`(그림·움직임). 사람 확인 목록이 남았으면 사용자에게 먼저 보인다 |

## 명령

```bash
node <플러그인>/scripts/voicecheck.mjs <에피소드>                      # 검사하고 고친다
node <플러그인>/scripts/voicecheck.mjs <에피소드> --no-fix             # 검사만
node <플러그인>/scripts/voicecheck.mjs <에피소드> --no-fix --out <폴더>   # 작업 폴더에 아무것도 쓰지 않고 검사만
```

- 기준 점수 `--min`(기본 0.85). 점수는 정규화한 두 글의 글자 단위 유사도(1이 같음)다. 정규화: 공백·문장부호·따옴표를 빼고, 아라비아 숫자를 한글 읽기로 바꾼다(`1914년` → `천구백십사년`). 인식 글의 숫자는 고유어 읽기(`19살` → `열아홉살`)로도 맞춰 보고 높은 점수를 쓴다.
- 배정표는 `--voices <파일>`, `out/voices.json`, `story.json`의 `voices` 순으로 찾는다. `--provider say`는 임시판 배정표를 만든다. 고치기 전에 배정을 검사하며 최종본은 서버의 복제 프로필까지 확인한다.
- 음성 인식은 `uv run --with faster-whisper`로 돈다. 모델 `large-v3-turbo`(약 1.6GB, 메모리 약 2GB, CPU)를 쓴다. 처음 한 번 내려받는다. 108문장에 약 16분 걸렸다(다른 렌더와 같이 돌 때). Bash 백그라운드로 돌린다. 더 가볍게 돌려야 하면 `--model small`.
- 고칠 때: 1번째 다시 만들기는 `say`를 숫자를 한글로 바꾼 글로 바꾸고 `take: 1`, 2번째는 `take: 2`(VoiceStudio는 조금 느리게 다시 만든다. seed는 목소리를 바꾸므로 그대로 둔다). 매번 다시 받아 적어 점수가 가장 높은 것을 `story.json`에 남긴다.
- **음성 생성과 음성 인식을 동시에 돌리지 않는다.** 스크립트는 받아 적기 → 다시 만들기 → 새 것만 받아 적기를 차례로 한다. 다른 세션이 VoiceStudio로 음성을 만들고 있으면 끝난 뒤에 돌린다.

## 결과 읽기

`out/voice-check.md`의 「사람 확인」에 기준 점수 아래 문장과 목소리 일관성에 걸린 문장이 나온다. 점수에 걸린 문장은 다음처럼 확인한다.

- **실제 오독**: 인식 글이 다른 말이다(낱말이 빠지거나, 다른 낱말로 읽거나, 숫자를 엉뚱하게 읽음). 다시 만들어도 안 되면 `say`를 직접 고친다(띄어 쓰기, 발음대로 쓰기, 문장을 둘로 나누기) → `build.mjs <에피소드> voice` → 다시 검사.
- **인식 쪽 오류**: 인식 글이 발음은 비슷한데 표기가 다르다(고유명사·외국 이름·사투리·드문 낱말. 예: 「한스」→「한수」). 음성은 맞을 가능성이 높으니 고치지 않고 사람 확인 목록에 「인식 쪽 오류로 보임」이라고 적는다.

「목소리 일관성」에는 배역별 문장 수와 평균 음높이, 확인이 필요한 문장이 나온다.

- 배정표에서 해설 수, `who` 누락, 나이 배역의 `base`를 검사한다. 배정 오류가 있는 문장은 그 사유를 기록하고 파일명 비교를 건너뛴다.
- 시간표의 파일명이 현재 목소리·읽는 글·반영된 지시·`take`로 예상한 이름과 다르면 배정과 캐시를 확인한다.
- 채택한 음성의 음높이가 같은 배역 평균에서 3반음 이상 벗어나면 「목소리 흔들림」으로 표시한다. 음높이를 잴 수 없는 문장은 평균에서 뺀다. `voice-check.json`의 문장별 `pitch`·`issues`와 후보별 `retries`에서 측정값과 사유를 볼 수 있다.

판단이 안 서는 문장은 사람이 들어 봐야 한다. 보고에 사람 확인 목록(장면 id, 문장, 인식 글)을 옮긴다. 음성 인식이 통과했다고 억양·감정까지 맞는 것은 아니다.
