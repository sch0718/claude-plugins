# 1. 이야기 수집

| | |
|---|---|
| 입력 | 주제·분위기(괴담, 감동, 반전, 실제 사건 등), 후보 수(기본 8개) |
| 출력 | `<작업 폴더>/collect/<날짜>-<주제>/index.md`(후보 목록), `01.md`, `02.md` … (후보마다 하나) |
| 다음 | `story-select`가 이 폴더를 읽고 점수를 매긴다 |

## 모으는 방법

1. 사용자에게 주제·분위기와 후보 수를 받는다. 창작 이야기면 이 단계를 건너뛰고 `story-outline`의 「창작 이야기」로 간다.
2. 웹 검색은 Sonnet 5.5 하위 에이전트에 맡긴다(`Agent`, `model: "sonnet"`). 검색어, 아래 「후보 파일」 형식, 「규칙」을 brief에 넣고 후보마다 파일 내용을 돌려받는다. 인앱 브라우저·Chrome 연동은 쓰지 않는다(검색 도구와 web-fetch 에이전트만).
3. 돌려받은 후보 중 두세 개의 출처 URL을 직접 열어 요지가 맞는지 확인한다. 규칙에 걸리는 후보는 파일을 남기되 index.md에 「제외(이유)」로 적는다.
4. 후보 파일과 index.md를 쓴다. 고르기는 하지 않는다.

## 후보 파일 (`01.md`)

뒤 단계(고르기·구성·검토)가 원문을 다시 열지 않고도 판단할 수 있게 쓴다. 원문 문장은 옮기지 않고 요지만 자기 말로 쓴다.

```markdown
# 01. <가제>

- 출처: <사이트·게시판 이름> 「<글 제목>」 <URL> (확인 <날짜>)
- 다른 출처: <URL> …
- 종류: 실제 사건 | 전해지는 이야기 | 도시전설 | 민담 | 커뮤니티 썰
- 화제 근거: 조회·추천·언급 수, 최근 기사·영상, 언제부터 회자되는지(숫자와 날짜로)
- 실화 여부: 확인됨(근거) | 불확실 | 지어낸 이야기로 알려짐

## 요지
누가, 어디서, 무슨 일이, 어떻게 끝났는지. 사건 순서대로 5~15문장.

## 핵심 사실
- 날짜·장소·인물·숫자처럼 영상에서 틀리면 안 되는 것. 출처끼리 다르면 둘 다 적는다

## 권리·위험
- 원작(소설·웹툰·영화 등) 여부, 실존 일반인 등장, 피해자 있는 사건 여부
```

## 후보 목록 (`index.md`)

| # | 가제 | 종류 | 한 줄 요약 | 출처 | 비고 |
|---|---|---|---|---|---|

## 규칙

- 원문을 베끼지 않는다. 사실관계와 줄거리만 가져오고, 대본은 나중에 새로 쓴다.
- 실존 일반인의 실명·신상(직장, 사는 곳, 얼굴)은 파일에도 적지 않는다. 공인이라도 확인되지 않은 의혹은 다루지 않는다.
- 저작권이 살아 있는 창작물(소설, 웹툰, 영화, 드라마, 게임, 다른 사람의 창작 괴담 연재 등)의 줄거리는 「제외」로 둔다. 저작권이 끝난 작품, 민담·전설, 출처가 흩어진 도시전설, 실제 사건은 된다.
- 피해자가 있는 실제 사건은 위험 칸에 적는다. 고르기 단계에서 사용자에게 묻는다.
