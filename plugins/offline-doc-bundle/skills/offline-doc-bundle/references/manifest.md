# 목차 manifest 형식

`bundle.py index --manifest manifest.json` 에 넘기는 JSON이다. 없으면 디렉터리 구조로 자동 생성되지만, 받는 사람이 처음 보는 화면이므로 직접 쓰는 편이 낫다.

```json
{
  "title": "프로젝트 문서 모음",
  "subtitle": "2026-09-16 팀 회의 · 예시 팀",
  "lang": "ko",
  "lead": "발표용 슬라이드 PDF는 <a href=\"발표자료.pdf\">여기</a>에 있습니다.",
  "notice": "<strong>사외 반출 금지</strong> — 사내 규정 원문이 포함되어 있습니다.",
  "sections": [
    {
      "name": "오늘 회의 자료",
      "desc": "회의에서 함께 보는 문서입니다.",
      "items": [
        {
          "path": "To-Be/19.발표자료.html",
          "title": "룰 유닛은 어떤 문서를 만들어야 하는가",
          "note": "발표자료 본문. 규정 조문으로 바로 이동할 수 있습니다.",
          "badge": "회의 자료"
        }
      ]
    }
  ]
}
```

| 필드 | 설명 |
|---|---|
| `title` · `subtitle` | 머리말. subtitle에 일자와 부서를 넣으면 나중에 찾기 쉽다 |
| `lead` | 머리말 아래 한 줄. PDF 링크를 걸어 두면 편하다. HTML 허용 |
| `notice` | 노란 경고 박스. 반출 금지·유효기간 같은 주의사항. HTML 허용 |
| `sections[].name` · `desc` | 분류 이름과 한 줄 설명 |
| `items[].path` | 루트 기준 상대 경로. 파일이 없으면 건너뛰고 경고한다 |
| `items[].title` | 생략하면 문서의 첫 `<h1>` 을 쓴다 |
| `items[].note` | 카드 설명. **이 문서를 왜 여는지** 쓴다 |
| `items[].badge` | 빨간 뱃지. 핵심 문서 한둘에만 |

## 분류 요령

**디렉터리가 아니라 읽는 사람의 목적으로 나눈다.** `To-Be/`, `As-Is/` 같은 작업용 구분은 받는 사람에게 의미가 없다.

실제로 잘 통한 분류:

| 섹션 | 무엇을 담나 |
|---|---|
| 오늘 회의 자료 | 회의 중 함께 보는 것. 1~2건 |
| 판정 근거 | "왜 그렇게 결론냈나"를 확인할 문서 |
| 이미 작성된 설계 | 인용한 기존 문서 |
| 배경과 분석 | 시간 날 때 읽을 것 |
| 규정 원문 | 조문 직접 확인용 |

**설명은 내용 요약이 아니라 여는 이유를 쓴다.** "체크리스트 20개 항목 대응"보다 "비해당 판정 근거를 확인할 때"가 낫다.

**순서는 읽는 순서대로.** 가장 먼저 볼 것을 맨 위에 둔다.
