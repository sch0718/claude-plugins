# doclookup

저장소 문서를 절 단위로 색인해 두고, 필요한 범위만 `파일:줄`과 짧은 문맥으로 돌려준다. 큰 문서를 통째로 읽거나 grep 결과를 손으로 모으는 대신 이것을 먼저 쓴다.

## 언제 쓰는가

- 큰 문서를 Read하거나 저장소를 grep하기 전: `search`·`section`으로 필요한 절과 줄을 찾은 뒤 Read의 `offset`·`limit`으로 그 범위만 읽는다.
- 용어·ID·절 제목·앵커를 바꾸기 전: `impact`로 같이 고칠 곳을 모두 받는다.
- 정합성을 확인할 때: 같은 용어의 다른 표기(`variants`), 설정에 없는 역할 명칭(`roles`), 깨진 링크·앵커(`links`).
- 설정의 확장이 `quotes` 같은 대조 명령을 줄 때, 인용을 고친 뒤 넘기기 전: `quotes`로 인용 문구와 조문 표기를 원문과 대조한다.

## 실행 방법

실행기는 이 스킬 폴더의 `bin/doclookup`이다. 스킬을 불렀을 때 보이는 Base directory 아래에 있다.

```bash
"<이 스킬 폴더>/bin/doclookup" search 변경수행자
```

- 작업 저장소 안에서 부르면 그 체크아웃에 맞는 설정을 찾는다. 다른 폴더를 보려면 `--root <폴더>`, 설정 찾기 대신 파일을 지정하려면 `--config <파일>`을 준다.
- 색인은 대상 파일이 바뀌었을 때만 다시 만든다. 따로 색인 명령을 부르지 않는다.
- 조회 명령(기본 명령과 `find`·`define`)의 종료 코드: 0 찾음, 1 없음, 2 설정·환경 문제. `quotes`는 아래 확장 명령의 종료 코드를 따른다.

## 명령

기본 명령은 `파일:줄`과 짧은 문맥을 돌려준다. 결과가 많으면 `--limit`까지만 보이고 남은 수를 적는다.

| 명령 | 하는 일 |
|---|---|
| `search <낱말> [--any …] [--in 경로] [--type …] [--files]` | 낱말과 그 표기 묶음이 쓰인 곳(띄어쓰기는 가리지 않는다). 첫 줄에 건수 많은 파일 5개를 보이고(모두는 `--files`), 줄은 설정한 우선 범위 → 원문 → 마크다운 → 텍스트 순이다 |
| `section <파일 또는 문서 이름> <앵커 앞부분 또는 제목 일부>` | 절 하나 |
| `id <ID> [--scope …]` | ID가 정의된 곳과 그 절 |
| `refs <대상>` | 대상(파일, `파일#앵커`, ID)을 가리키는 링크·앵커·ID 출현 |
| `impact <낱말 또는 ID 또는 파일#앵커>` | 바꾸면 같이 고쳐야 할 곳 전체. 마크다운과 텍스트 파일(스크립트)을 나눠 파일별 건수와 줄을 보인다. 줄은 파일마다 `--per-file`까지 |
| `variants <낱말>` | 묶음에 없는 비슷한 표기 후보(띄어쓰기만 다른 꼴, 접미사 짝, 같은 줄기에 다른 꼬리). 모두 「후보」로 표시한다 |
| `roles` | 설정의 역할 명칭 꼴인데 역할 목록에 없는 낱말과 그 위치 |
| `links` | 깨진 링크·앵커 목록 |

범위를 둔 ID(예: 시스템마다 번호가 따로인 결정·제약 번호)는 `--scope`를 주지 않으면 범위별로 나눠 보이고 「범위 불명」 묶음을 따로 보인다.

저장소 설정에 확장이 있으면 확장이 더하는 명령(예: `find`, `define`)도 같은 실행기로 부른다. 어떤 명령이 있는지는 그 저장소 설정의 `[[extensions]]`에 적혀 있다.

### 확장이 주는 대조 명령(quotes)

| 명령 | 하는 일 |
|---|---|
| `quotes [md 파일…] [--all] [--json]` | 「」·『』 인용 문구가 원문에 있는지, 적은 조가 아닌 다른 조에 있는지, `[규정] 제N조④ 3호` 같은 조문 표기가 원문에 있는지 대조한다 |

인용을 고친 뒤, 다른 사람에게 넘기기 전에 돌린다. md 파일 인자는 저장소 루트(`--root`, 주지 않으면 체크아웃 최상위) 기준 상대 경로나 절대 경로다. 하위 폴더에서 불러도 그 폴더 기준이 아니다. 파일을 주지 않으면 확장이 정한 기본 문서를 본다. 출력은 확장의 텍스트나 JSON 그대로다.

- 종료 코드 0: 문제 없음.
- 종료 코드 1: 문제 있음. 보고된 문제(`파일:줄`)를 사용자에게 보이고, 다른 검색(grep 등)으로 넘어가지 않고, 보고된 `파일:줄`만 열어 인용·조문 표기를 고친 뒤 다시 돌린다. 출력에 대조 결과가 없고 표준 오류에 traceback만 있으면 확장이 실패한 것이므로 표준 오류를 그대로 보인다.
- 종료 코드 2: 문서·원문 없음, 또는 설정·환경·사용법 문제. 표준 오류 메시지를 그대로 보이고 그 내용으로 원인을 가려 인자 경로나 원문 위치를 확인한다. 표준 오류에 `invalid choice: 'quotes'`가 있으면 설정이나 확장에 `quotes`가 없다는 뜻이므로 설정과 확장을 확인한다. 설정 생성은 묻지 않는다. 표준 오류가 설정을 찾지 못했다는 메시지(시도한 저장소 키 등)일 때만 아래 「설정이 없을 때」를 따른다.

`links`는 깨진 링크·앵커와 대상 없는 원문 인용을 찾는다. `quotes`와 겹치는 것은 조문 표기 확인뿐이다.

## 지킬 것

- 조회 명령(기본 명령과 `find`·`define`)은 결과가 없을 때(종료 코드 1)만 grep·Read로 넘어간다. 결과가 있으면 그 `파일:줄`을 근거로 필요한 범위만 읽는다. `quotes`는 위의 후속 행동을 따른다.
- `impact`가 보인 파일을 모두 확인하기 전에는 「다 고쳤다」고 하지 않는다. 남은 수(`… k건 더`)가 있으면 `--per-file`·`--limit`을 늘려 다시 본다.
- 「후보」로 표시된 결과(`variants`)는 사람이 확인하기 전에 표기 묶음으로 쓰거나 일괄 치환하지 않는다.

## 설정이 없을 때(종료 코드 2)

조회 명령(기본 명령과 `find`·`define`)과, 설정을 찾지 못한 `quotes`에 적용한다.

표준 오류에 시도한 저장소 키, 찾아본 폴더, 새 설정을 둘 경로와 최소 예시가 나온다.

1. 그 메시지를 사용자에게 그대로 보인다.
2. 설정을 새로 만들지는 사용자에게 묻는다. 만든다면 환경 변수 `DOCLOOKUP_CONFIG_DIR` 폴더에 둔다. 환경 변수가 없으면 기기 설정 폴더(예: `~/.config/doclookup/repos`)를 만들고 `~/.claude/settings.json`의 `env`에 `DOCLOOKUP_CONFIG_DIR`로 등록한 뒤 거기 둔다. 플러그인 폴더는 업데이트 때 바뀌므로 쓰지 않는다. 작업 저장소 안에는 만들지 않는다.
3. 설정이 생기기 전까지는 grep·Read로 일한다.

Python 3.11 이상을 찾지 못해도 종료 코드 2다. 이때도 사용자에게 알리고 grep·Read로 일한다.
